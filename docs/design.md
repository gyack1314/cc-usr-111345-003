# 分组有序聚合状态设计

## 1. 目标与边界

服务质量仓需要在**可撤回、可更正**的明细上回答当前版本的精确分位与排名查询。
只存压缩分位摘要不可逆：撤掉一批重复请求后无法从摘要里减掉它们，重扫全月
又太慢。本设计用落盘的**函数式有序 treap + 行身份账 + 批事务回执**替代摘要，
保证可逆、精确、有界。

硬约束：

* 每组可能很大，不能把整组拉进 Python 内存，也不能每次从明细重建排序；
* 更新与点分位查询受明确的**打开文件预算**与**节点缓存预算**限制；
* 小批更正只访问受影响分组与必要的秩路径；
* 结果必须精确，连续分位以有理数（`fractions.Fraction`）给出，不用近似。

## 2. 存储布局

```
<state-dir>/
  STATE_MARKER          # writable 或 readonly-export 标记
  writer.lock           # O_CREAT|O_EXCL 排他写者锁
  catalog.db            # 目录库：全局身份账、分组计数、批事务日志、序列
  shards/g<gid>.db      # 每个分组（租户,日期）一个分片
```

### 2.1 目录库 `catalog.db`

| 表 | 职责 |
|---|---|
| `groups` | 分组键 -> 分片路径，缓存 `COUNT(*)`/非空/null 三个计数 |
| `identity` | 全局 `row_id -> gid` 身份账，撤回/跨组更正/合并冲突的点查入口 |
| `batches` | 批事务日志：`INTENT -> COMMITTED`，含规范化摘要、载荷、**已解析计划** |
| `seq` | gid 等序列 |

### 2.2 分组分片 `g<gid>.db`

| 表 | 职责 |
|---|---|
| `nodes` | 函数式 treap 节点：`value, multiplicity, priority, left_id, right_id, subcnt, version` |
| `ledger` | 分片内 `row_id -> 完整当前像`，旧像校验的权威依据 |
| `applied` | 已提交批回执 `(batch_id, digest)`，使重放幂等 |
| `sources` | 来源身份清单，合并时据此检测交叠 |
| `meta` | 当前根、版本、三个计数 |

treap 节点带 `subcnt = 左子树 subcnt + 本节点重数 + 右子树 subcnt`，
因此 `kth`、`count_lt/le`、秩定位都只走 O(log n) 秩路径。重复值不展开成
多行，而是累计到单节点 `multiplicity`，超大重复值组只占一个值节点。

## 3. 函数式（持久）treap 与版本

* 节点**不可变**。插入/撤回/更正沿访问路径克隆节点，未触碰的子树直接复用，
  旧根仍可被保留期内的读句柄完整遍历——旧读句柄稳定由结构本身保证。
* 新节点先进入待刷缓冲，分片提交时一次 `executemany` 批量落盘。
* 提交后做垃圾回收：用 SQLite 递归 CTE 求“当前根 ∪ 所有活跃快照根”的可达集，
  删除不可达历史节点。活跃快照根始终被钉住，GC 不会破坏旧句柄。
* 中序遍历用显式栈（栈深 O(log n)）流式产出，秩区间查询先沿一条秩路径定位
  起点，再走中序后继，访问量 O(log n + 输出值节点数)。

## 4. 批事务与崩溃恢复

一个批次的生命周期：

1. **纯读全量校验**（不建组、不写盘），收集全部错误后一次性拒绝整批：
   批内 ID 重复、撤回不存在、旧像不一致、同 ID 不同内容、重数减负、形态非法。
2. 把操作解析成与崩溃时刻无关的**固定计划**：坐标全部落成真实 gid，
   含每分片动作序列与全局身份账调整，随 `INTENT` 持久化。
3. 逐分片开事务：改 treap、改身份账/来源、写 `applied` 回执、提交。
4. 目录库 `batches` 标记 `COMMITTED`。

崩溃注入点：`after_intent`、`after_shard`（每个分片后）、`after_commit`。

重开引擎时扫描 `INTENT`：按持久化计划重放，分片 `applied` 回执让已提交的
分片跳过，因此**重试不重复累计**。计划不依赖当前身份账，避免跨组更正崩溃后
被错误重新推导。同 `batch_id` 重试：摘要一致则幂等返回，摘要不一致则拒绝。

## 5. 计数与精确分位

* `COUNT(*)`（含 null）与非空计数、null 计数分别维护；treap 只索引非空值。
* **空组**（`COUNT(*)=0`）与**全 null 组**（非空计数为 0）是两种不同异常，
  不会混同。
* 连续分位：位置 `h = p*(n-1)`，`p` 为整数比；取下标 `floor(h)`、`ceil(h)`
  的值线性插值，全程整数/分数运算，返回 `Fraction` 与两端值、秩。
* 查询：`count_less`（严格小于）、`count_leq`（小于等于）、
  `value_multiplicity`、`rank_range(lo, hi)`（返回值与重数，跨 treap
  版本块的重复值通过重数聚合，不漏算）。

## 6. 资源预算与计量

`Budget(open_shards, cached_nodes, open_snapshots)` 全部为硬上限：

* 写路径分片连接走有界 LRU，超预算淘汰并关闭连接；
* 每个 treap 访问器的节点缓存走有界 LRU，物理节点读取计入 `node_loads`；
* 旧读句柄的只读连接单独有预算并计量淘汰。

`Stats` 同时给累计计数（节点命中/未命中、物理读取、SQL 条数、流式扫描行数、
写入/GC 节点数、身份账点查）与峰值（缓存大小、打开分片、打开快照）。
测试据此断言峰值不破预算，且大组下节点表按去重值有界。

## 7. 合并与只读导出

* **合并**：逐分片只读打开来源，先比对 `sources` 来源身份清单——交叠即拒绝；
  再做 `row_id` 级交叠深度防御。通过后以普通插入批事务并入，合并结果保留完整
  身份账，仍可按原 `row_id` 撤回。不是简单把计数相加。
* **只读导出**：只复制 treap、计数与来源清单，**不带身份账与回执**；目录写
  `readonly-export` 标记。可写引擎打开该目录会被拒绝，导出对象的写入口显式
  抛 `ReadOnlyExportError`，因此无法以同一种状态类型接收更新。

## 8. 模块一览

| 模块 | 职责 |
|---|---|
| `treap.py` | 落盘函数式 treap：split/merge、增量、秩查询、流式遍历、GC、批量构建 |
| `shard.py` | 分片 SQLite 结构、身份账、回执、来源、事务 |
| `catalog.py` | 目录库、全局身份账、批日志、排他锁 |
| `ops.py` | 操作规范化、旧像比较、分组动作计划（校验与写入共用） |
| `engine.py` | 校验、批事务、恢复、查询、快照、预算池 |
| `merge.py` / `export.py` | 分片合并 / 只读导出 |
| `rational.py` | 精确分位与有理结果 |
| `reference.py` | 独立全排序参考实现（测试预言机，逻辑与引擎完全不同） |
| `budget.py` | 预算、LRU、计量 |
